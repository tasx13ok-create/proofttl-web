ProofTTL / methodology

Verification Methodology v1

Methodology version: proofttl-methodology-v1. Lease issuance attestation schema: proofttl-issuance-v1. Signature envelope: proofttl-ed25519-v1.

SUPPORTEDCONTRADICTEDUNKNOWN

ProofTTL evaluates one explicit claim against one supplied public source. A verdict is scoped to that claim, that source, and the observation time; it is not a universal statement about reality.

Decision criteria

SUPPORTED means the fetched source provides evidence that supports the claim under the active verifier. CONTRADICTED means the source provides evidence incompatible with the claim. UNKNOWN means ProofTTL cannot responsibly maintain either conclusion from the available source, including fetch failures, insufficient evidence, ambiguous evidence, or proof-basis guard failures.

Proof basis

Exact-text matches can use the deterministic EXACT_TEXT basis. Other claims use the semantic verification path. When an originally exact piece of evidence disappears after a source change, ProofTTL applies a proof-basis guard rather than silently keeping the old supported state.

Source acquisition

Only allowed public HTTP(S) sources pass SSRF/public-network validation. Redirects and source size are bounded. A blocked, unavailable, authenticated, paywalled, or otherwise inaccessible source can result in UNKNOWN / source-unavailable behavior instead of an invented verdict.

Monitoring and state changes

An issued Lease starts ACTIVE. While active, automatic monitoring checks the source on a schedule derived from the Lease TTL. Unchanged source fingerprints avoid unnecessary semantic work. If the source changes and the original verdict can no longer be maintained before expiry, the Lease can become REVOKED. Once its TTL ends, it becomes EXPIRED.

Each stored Lease contains a verification history with check time, result, status, source fingerprint when available, evidence/reason, confidence, and verifier details. Revocation includes the previous/current status and the current evidence state.

Confidence

Confidence is evidence-strength metadata from the active verifier, not a probability that reality itself is true. It must be interpreted together with the verdict, source, proof basis, and reason.

Cryptographic issuance signature

The immutable issuance attestation is signed with Ed25519 when signing is enabled. Mutable monitoring fields are intentionally outside the issuance signature so a Lease can later become revoked or expired without invalidating the historical statement that was signed at issuance.

Published verification keys are available from the API key-discovery endpoint. Use the independent browser verifier to check a Lease locally.

Current network status

The current x402 settlement network is Base Sepolia testnet. Testnet settlement is intentionally distinguished from production mainnet payment settlement.

Scope rule

ProofTTL verifies what a source supports now. A Fact Lease is intentionally time-limited and source-scoped. Expiry and revocation are product behavior, not failures of the original issuance signature.
